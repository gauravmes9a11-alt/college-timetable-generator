It provides a record of the team's Jira workspace, including the project dashboard, backlog views, sprint boards and sprint reports.

## 3. Jira Work Management

The Jira workspace was used to organize and document the project through:

- Creation and organization of project work items.
- Assignment of responsibilities among team members.
- Estimation of tasks using story points.
- Allocation of work across the two planned sprints.
- Recording of due dates and workflow statuses.
- Monitoring work through the To Do, In Progress, In Review and Done stages.
- Generation of burndown and burnup reports to visualize sprint activity.

The project uses the `SCRUM` work-item key prefix.

## 4. Tracking Timeline and Integration Context

The project implementation was completed before the Jira-based sprint-tracking workflow was configured.

The instructor-provided sprint schedule began on **27 October 2026**. However, Jira tracking was set up from **29 October 2026**, after the implementation work had already taken place.

Consequently, the Jira work items, estimates, assignees, sprint allocations and status records were entered retrospectively to document the completed project work against the planned sprint structure.

The GitHub repository was connected to Jira after the implementation phase. Since the earlier commits and pull requests had already been created without Jira issue keys, the integration could not automatically establish retrospective associations between those development activities and the corresponding Jira work items.

Therefore, the Jira reports and screenshots represent the records maintained in the configured Jira workspace; they should not be interpreted as a complete, continuously maintained development history from the original Sprint 1 start date.

## 5. Reporting Notes

The burndown and burnup charts are to provide views of sprint activity:

- **Burndown:** Tracks the remaining estimated work over the sprint.
- **Burnup:** Tracks completed work in relation to the recorded sprint scope.

The dashboard, backlog and board screenshots provide additional context about project organization, team responsibilities and recorded workflow status.

Together, these records document the Jira project-management activities carried out for our College Timetable Generator project.
